# Real-time gateway events: research findings (as of 23 Oct 2026)

Method: Microsoft Learn pages, the fabric-cicd and terraform-provider-fabric docs, the Terraform registry API and the Azure Retail Prices API. Nothing was signed in to or changed.
Tags used: [OFFICIAL] = Microsoft doc or source. [COMMUNITY] = non-official or old source. [UNVERIFIED] = could not confirm. Learn page "updated" dates are quoted where they matter.

## 2.1 APIM Basic v2 / Standard v2: log-to-eventhub and Event Hub loggers
- [OFFICIAL] https://learn.microsoft.com/en-us/azure/api-management/log-to-eventhub-policy (updated 2026-08-19): "APPLIES TO: All API Management tiers"; Usage "Gateways: classic, v2, consumption, self-hosted"; sections inbound, outbound, backend, on-error; scopes global/product/API/operation. Not affected by App Insights sampling (every invocation logged). Max message 200 KB (truncated beyond). Attributes: `logger-id`, `partition-id` or `partition-key` (expressions allowed for partition-key). Important note: logger access is not checked at policy save, anyone who can write a policy can send to any logger.
- [OFFICIAL] https://learn.microsoft.com/en-us/azure/api-management/api-management-howto-log-event-hubs (updated 2026-06-25): "All API Management tiers". Managed identity is the recommended option: system- or user-assigned identity, role **Azure Event Hubs Data Sender** on the namespace or event hub; logger body `loggerType: azureEventHub`, `credentials: { endpointAddress: <namespace host name>, identityClientId: <client id or SystemAssigned>, name: <event hub name> }`. Connection string (Send permission) is the alternative. Not available in workspaces. Event Hubs can be in another subscription/tenant.
- Network: Event Hubs must be reachable by APIM; Eventstream also needs it publicly reachable (see 2.3), so public endpoint is the simple path for both.

## 2.2 Event Hubs (Australia East) tiers and prices
- [OFFICIAL] https://learn.microsoft.com/en-us/azure/event-hubs/compare-tiers (updated 2026-08-26): Basic: 1 consumer group per event hub, max retention 1 day, publication 256 KB, no Capture, no IP firewall / private link, no Kafka, 100 brokered connections. Standard: 20 consumer groups, retention up to 7 days, 1 MB, Kafka, IP firewall, Private link, Capture priced separately, 40 TU max. "Choose Basic for simple, low-volume streaming where you need a single consumer group and short retention."
- Prices [OFFICIAL: Azure Retail Prices API, armRegionName australiaeast, currencyCode AUD, queried 2026-10-23]: Basic throughput unit A$0.0214/h (about A$15.6/month); Standard throughput unit A$0.0427/h (about A$31.2/month); ingress events A$0.0399 per million events (Basic and Standard, same). Standard Capture A$0.1425/h (not needed). A "Standard Kafka Endpoint" meter at A$0.1282/h still appears in the price list (2018 start date); the tier-comparison page no longer prices Kafka separately, so treat that meter as legacy [UNVERIFIED whether it is billed]. At a few hundred events per session the ingress cost is effectively zero; the cost is the standing namespace (TU billed per hour whether used or not): so decide bootstrap-standing (about A$0.5 to 1/day) versus per-session create/destroy (then Eventstream's source connection must be re-created every session).
- Basic vs Eventstream: official Eventstream page documents the consumer group field with default `$Default` and does not state a tier requirement (https://learn.microsoft.com/en-us/fabric/real-time-intelligence/event-streams/add-source-azure-event-hubs, updated 2026-09-29). [COMMUNITY, Feb 2024 MSSQLTips walkthrough] says Basic could not be chosen/`$Default` not supported then; this is old and unconfirmed against current Fabric behaviour. Safe plan: Standard (one extra consumer group `eventstream`, +A$15.6/month vs Basic); test Basic first only if you want to save that and accept a failure risk. Event Hubs retention matters when Fabric capacity is paused: Basic keeps 1 day, Standard 7 days, so events from a burst survive a paused F2 only if consumed/resumed within that window.

## 2.3 Eventstream source "Azure Event Hubs": auth, tier, trial
- [OFFICIAL] same page: prerequisites = workspace on Fabric capacity or trial license mode, Contributor or higher; "Appropriate permission to get an event hub's access keys"; the event hub must be publicly accessible and not behind a firewall unless connected through a managed private endpoint. Auth options: **Shared Access Key** (key name + key; "Basic" feature level) and, with "Extended features": **Workspace identity** (enable it in workspace settings, assign the workspace identity the **Azure Event Hubs Data Receiver** role on the event hub/namespace, data gateway = none for public). Formats JSON, Avro, CSV. Schema-aware Eventstream is preview; the plain Event Hubs source is not marked preview.
- No documented support for user-assigned managed identity of your own or an app registration (service principal) for this source on that page; workspace identity is the keyless route (the p9 Terraform already creates workspaces with `identity = SystemAssigned`; whether it is already enabled: [REPO infra/fabric/main.tf]).
- Workspace identity: [OFFICIAL] https://learn.microsoft.com/en-us/fabric/security/workspace-identity (2026-09-16): GA; "You can create and use a workspace identity regardless of the capacity SKU"; "Using workspace identity as a credential in cloud connections is supported in any capacity" (trusted workspace access needs an F SKU, not relevant here). Workspace identity is not supported in B2B/cross-tenant scenarios.
- Eventstream capacity use [OFFICIAL] https://learn.microsoft.com/en-us/fabric/real-time-intelligence/event-streams/monitor-capacity-consumption (2026-09-29): Eventstream Per Hour 0.222 CU-hours per hour; Data Traffic 0.342 CU-hours per GB; Processor starts at 0.778 CU-hours per hour (Low throughput) and autoscales; Event Hubs/IoT Hub pulled via the processor (no connector vCore charge). "Eventstream Per Hour is charged only when it's active ... If no traffic flowed in or out for the past two hours, no charges apply." "Eventstreams can operate with the smallest F capacity." So about 1.0 CU of an F2's 2 CU while events flow.
- Pause behaviour [OFFICIAL same page]: when capacity is paused all eventstream sources/destinations pause; on resume an Active eventstream's sources/destinations "start data ingestion after you activate them" (an Inactive one must be resumed manually). So after each F2 resume, check the eventstream is running.
- Trial: no restriction listed for Eventstream; features-by-SKU page says a trial capacity does not support the listed items (Copilot, ARM/Terraform for capacity, trusted workspace access, managed private endpoints is supported on trial per its footnote); Eventstream/Eventhouse/Dashboard/Activator are not on that list. [OFFICIAL https://learn.microsoft.com/en-us/fabric/enterprise/fabric-features, 2026-06-30].

## 2.4 Eventhouse / KQL database: trial or F2, always-on, OneLake availability
- Availability: Eventhouse is on trial and on F SKUs, no SKU restriction on the pages read (above). [OFFICIAL]
- Cost model [OFFICIAL https://learn.microsoft.com/en-us/fabric/real-time-intelligence/kql-database-consumption, 2026-06-16; https://learn.microsoft.com/en-us/fabric/real-time-intelligence/eventhouse, 2026-09-09]: compute is "Eventhouse UpTime" (seconds active x virtual cores), autoscaled; "Your eventhouse is designed to optimize cost by suspending the service when not in use. When reactivating the service, you might encounter a latency of a few seconds." **Capacity Planner mode** (formerly Always-on) keeps it permanently active and the default minimum is 2 CUs (25 GB); do NOT enable it on F2 (2 CU would be the entire capacity). Without it, the bursty pattern suits Eventhouse: idle = suspended = no UpTime. Scheduled changes take up to 30 min to apply.
- Storage billed separately from CU: OneLake Cache Storage (premium, cache policy) + OneLake Standard Storage (retention policy). Negligible at these volumes.
- Throttling levels: proactive (queries throttled), reactive (ingestion and queries paused, no data lost), extreme reactive (data may be lost after a period) [OFFICIAL]. Risk on F2: Eventstream (about 1 CU) + Eventhouse + dashboard auto-refresh queries + Activator, all within 2 CU; p9 batch jobs must not run at the same time. Smoothing behaviour of Eventhouse vs the F2 limit is not documented in what I read [UNVERIFIED].
- OneLake availability [OFFICIAL https://learn.microsoft.com/en-us/fabric/real-time-intelligence/event-house-onelake-availability, updated 2026-09-09]: enable on database or table; "Apply to existing tables" backfills history; Delta Lake in OneLake, query from Lakehouse/Warehouse/notebooks/Direct Lake; **a OneLake shortcut from a lakehouse is supported**; no extra storage cost; retention policy of the KQL db also applies to the OneLake copy (data removed from the db is removed from OneLake); turning it off soft-deletes the OneLake copy. While it is on you cannot rename tables, alter a column type (add/drop column ok), apply row-level security to tables, or delete/truncate/purge data (turn off, do the task, turn on). Prerequisites: Fabric-enabled capacity and a KQL database with edit permissions and data (for table-level enabling).
- **Latency (changes the plan's "same events feed both the dashboard and project 9's star schema"):** Eventhouse batches into Parquet adaptively; default `TargetLatencyInMinutes` is "Up to 3 hours, or until files of sufficient size (typically 200-256 MB) are created"; allowed 5 minutes to 3 hours; set with `.alter-merge table <T> policy mirroring dataformat=parquet with (IsEnabled=true, TargetLatencyInMinutes=5)`; shorter delay "might result in a suboptimal delta table with a large number of small files ... read-only and can't be optimized"; check lag with `.show table mirroring operations` (Latency 00:00:00 = fully available). With a few hundred events per session and an F2 that is paused at session end, the default would leave the data not yet in OneLake when the capacity is paused; set 5 minutes. Whether the flush happens while the capacity is paused is [UNVERIFIED], and whether a shortcut to an Eventhouse table in a workspace whose capacity is paused is readable is [UNVERIFIED] (probably not).
- Schema sync + SQL analytics endpoint on the KQL db is available when OneLake availability and schema synchronization are on.

## 2.5 Real-Time dashboard and Activator: trial / F2, alert sources, channels
- Real-Time dashboard prerequisites: a workspace with a Fabric-enabled capacity and a KQL database with data [OFFICIAL https://learn.microsoft.com/en-us/fabric/real-time-intelligence/dashboard-real-time-create, 2026-10-22]; no SKU restriction listed. Auto refresh `minInterval` in the exported JSON schema is "5m" (example file; `defaultInterval` 15m); **Live refresh** exists (Manage > Refresh settings) [OFFICIAL]. Export/import as JSON ("Replace with file"), used for version control. Viewers need the Real-Time Dashboard permissions; free-licence/F64 viewer rules from the Power BI side were not stated on this page [UNVERIFIED for dashboards].
- Activator (GA since Nov 2024) [OFFICIAL https://learn.microsoft.com/en-us/fabric/real-time-intelligence/data-activator/activator-introduction, 2026-10-13]: sources = Eventstream, Fabric/Azure events, Power BI visuals, Real-Time dashboard tiles, KQL queryset (see eventhouse-compute-observability), business events, warehouse SQL query (preview). "You only incur cost when activators are actively running." Pay-as-you-go retail meter lists "RTI Event Listener and Alert" at the same A$0.2992 per CU-hour as capacity usage [Retail Prices API].
- Alert from a dashboard tile = a KQL query run on a schedule (default every 5 minutes), "On each event when" (no dimensions) or "On each event grouped by" (dimensions), occurrence count; limits: only tile types Time chart, Bar, Column, Area, Line, Stat, Multi stat, Pie; tile must be KQL-based, a predefined time range (no custom range), at most one time range, no `make-series` data; a time-chart point is read only once, so exclude the current bin or use a Stat/KPI tile [OFFICIAL activator-get-data-real-time-dashboard + activator-limitations]. Stat/bar tiles grouped by user per minute are the workable shape for a "per-user token spike".
- Alert from an Eventstream: rules per object (group key e.g. user), stateless (value < N, `BECOMES`) and stateful (INCREASES, EXIT RANGE, heartbeat); stateless rules respond in milliseconds, aggregation rules depend on lookback; the "failover to second region" rule is a simple stateless `backend == secondary` on each event (note: with priority-1/2 pool, secondary traffic is only failover). Max 10,000 events/s per rule, 500 rules per Activator item [OFFICIAL activator-limitations].
- Delivery channels [OFFICIAL]: email, Teams (message to individuals, group chat, channel post per the dashboard page; the limitations page says "Teams channels aren't currently supported" , the two pages conflict), Fabric items (pipeline, dataflow, notebook, Spark job, User Data Function, Copy job, business event preview), Power Automate custom action. **Email recipients must be internal**: same domain as the creator or a verified domain on the tenant; no external or guest addresses. For a personal-tenant owner: send to the owner's own tenant address. Limits 30 emails/rule/recipient/hour, 500/Activator item/hour.
- Capacity-use from Activator is small but nonzero; no trial exclusion listed.

## 2.6 Git integration / fabric-cicd status
- Git integration (GitHub supported) [OFFICIAL https://learn.microsoft.com/en-us/fabric/cicd/git-integration/intro-to-git-integration, 2026-10-17]: Real-Time Intelligence items Activator, Eventhouse, Eventstream, KQL database, KQL queryset, Real-Time Dashboard listed WITHOUT a preview tag (GA); Event Schema Set, Digital twin builder, Anomaly detection are preview. But https://learn.microsoft.com/en-us/fabric/real-time-intelligence/git-deployment-pipelines (2026-06-17) lists "Activator (preview)" for Git; the two pages disagree, treat Activator git as preview/unsure. Deployment pipelines also supported for these items. Limitations there: keep Eventstream destinations in the same workspace; an Eventstream with an Eventhouse destination in **Direct Ingestion** mode needs manual reconfiguration of that connection after import/deploy to another workspace; use Variable Library connection references.
- Activator lifecycle limits [OFFICIAL activator-limitations]: Activator items using Azure Blob Storage events, Power BI as source, or User Data Functions as action cannot be committed/deployed. Eventstream- and dashboard-sourced rules are not in that list.
- fabric-cicd 1.4.0 (2026-10-07) supported types include Eventhouse, Eventstream, KQLDashboard, KQLDatabase, KQLQueryset, Reflex [OFFICIAL, from the project 9 research `E:\Projects\Fabric\docs\research\2026-10-22-fabric-facts.md` section 3 and https://microsoft.github.io/fabric-cicd/latest/reference/item_types/]. Item notes from that page:
  - Eventstream: destinations pointing to items in another workspace stay pointed at the original unless parameterised; same-workspace destinations re-pointed automatically; a lakehouse destination needs the table to exist on first deploy.
  - Eventhouse: `find_replace` NOT applied; `exclude_path` is required when deploying an Eventhouse attached to a KQL database; unpublish off by default (`enable_eventhouse_unpublish`); streaming data may differ between source and deployed.
  - KQLDatabase: not a standalone item, files sit in a `.children` folder under the Eventhouse; `find_replace` NOT applied; table data is not source-controlled.
  - KQLQueryset / KQLDashboard: point at the original KQL database unless parameterised; the cluster/query URI must be present in the JSON for rebinding; same-workspace case handled automatically. Dynamic variable `$items.Eventhouse.<name>.$queryserviceuri` exists for this.
  - Reflex: `find_replace` NOT applied; initial deployment "may not reflect streaming data immediately"; "Source control may not support all activators/reflexes, as not all sources are compatible"; "Reflex" is the item name in source.
  - Preview status is not stated on that page. No fabric-cicd page I read marks these as preview.
- Practical: git/fabric-cicd round-trip of Eventstream (with a connection to the Event Hub) needs a Fabric connection (shared-key or workspace-identity based) that is not source-controlled; the executing identity needs access to the connection. The Event Hub namespace/hub names would sit in the Eventstream definition in the repo (not secrets, but they are resource names: parameterise or accept).

## 2.7 Terraform microsoft/fabric provider
- Latest 1.14.0 (2026-09-17) [OFFICIAL registry API]; the p9 stack pins `~> 1.14`. Resource docs exist in `main`: `fabric_eventhouse`, `fabric_kql_database` (ReadWrite or shortcut; with or without definition), `fabric_eventstream` (definition bootstrapping or update), `fabric_kql_queryset`, `fabric_kql_dashboard`, `fabric_activator` [OFFICIAL github docs/resources]. Only `fabric_activator` carries a preview banner ("must explicitly enable the preview mode in the provider configuration", `preview = true`); the others have no preview note and state Service Principal authentication is supported.
- Gaps: provider cannot assign a capacity (spec amendment 1 in p9: trial capacity is assigned in the UI; on F2 `capacity_id` could be used via the Fabric capacity data source [UNVERIFIED]); Terraform/ARM for a Fabric capacity (azurerm_fabric_capacity) is F-SKU only, not trial. No provider resource for the OneLake-availability setting or the mirroring policy: use a KQL command (`.alter-merge table ... policy mirroring`) or the UI/REST [UNVERIFIED that no REST/Terraform setting exists]. KQL tables/functions/materialized views come from the KQL database definition (`DatabaseSchema.kql`) or KQL commands. The Eventstream's Event Hubs source needs a Fabric connection ("fabric_connection" exists in the provider [UNVERIFIED whether it supports Event Hubs SharedAccessKey/workspace identity]).
